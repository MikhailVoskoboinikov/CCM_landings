# Лендинги учебного центра ЦКМ

Публичные страницы курсов учебного центра Центра корпоративной медицины для
Узбекистана и Кыргызстана. Первая часть платформы: лендинги → заявки и CRM → LMS
с проверкой сертификатов по QR. Заказчик и единственный, кто утверждает решения, — Родион.

## Устройство репозитория

| Папка | Что это |
| --- | --- |
| `landing/` | Лендинги: Astro 7 + React-островки, Tailwind 4, shadcn/ui (radix, lucide), Motion |
| `maket/` | Ранний HTML-макет: справочник по текстам и структуре, в сборку не входит |
| `backend/` | FastAPI + Postgres + Redis — приём заявок, CRM, LMS. Ещё не создан |
| `app/` | React + Vite + shadcn — интерфейсы LMS и CRM. Ещё не создан |

Стек совпадает со стеком Родиона (FastAPI, React, shadcn, lucide, Postgres, Redis),
кроме самих лендингов: они на Astro, потому что почти весь трафик — телефоны из
рекламы Instagram, и страница должна приходить готовым HTML, а не собираться из JS.

## Лендинги (`landing/`)

- **Адреса:** `/{страна}/{курс}` — `/uz/bls`, `/kg/first-aid-kids`. Страна задаёт
  контакты, валюту, юрлицо и порядок мессенджеров. Язык пока один — русский;
  узбекский, киргизский и английский добавятся префиксом, язык по умолчанию будет
  выбираться по браузеру и стране.
- **Стенд `/playground/{страна}/{курс}`** показывает все варианты всех блоков на
  реальных данных, с комментариями и списком вопросов к ЦКМ. Выбор и комментарии
  хранятся в localStorage, обмен — экспорт и импорт JSON.
- **Данные** — `src/data`: курсы (`courses/*.ts`), страны, фото. Тексты живут только там;
  блоки их рисуют. Отличия курса в конкретной стране — `byCountry` в данных курса;
  страницы берут курс через `courseFor(курс, страна)`, который сливает их с общими данными
  (вложенные объекты сливаются, массивы заменяются целиком). Условий вида «если
  Узбекистан и BLS» в блоках нет.
- **Факты из материалов ЦКМ.** Бишкек: юрлицо, лицензия, инструкторы, клиенты, цены для
  организаций, срок и доставка сертификата ERC, цифра про скорую — из презентации учебного
  центра. Ташкент: юрлицо и проверка сертификата — с образца сертификата.
- **Блоки** — `src/components/blocks/*.astro`, у каждого проп `variant`.
  Реестр блоков, их порядок и варианты боевых страниц — `src/config/blocks.ts`
  (`DEFAULTS`); кнопка «Скопировать выбор» на стенде выдаёт JSON для него.
  `Block.astro` — единая точка входа для страниц и стенда.
- **Интерактив** — React-островки: `LeadSheet` (нижняя шторка заявки, открывается
  любым элементом с `data-lead-open`), `LeadForm`, `PriceCalc`, `Tilt`. Всё остальное —
  статичный HTML и несколько строк скрипта.
- **Телефон и компьютер.** Варианты `adaptive` собраны из двух других: одна версия
  блока для телефона, другая для компьютера (`md:hidden` / `hidden md:block`). Так
  устроены первый экран (фото на весь экран / кардиограмма), «Для кого» (список /
  плитки) и программа (раскрывающийся список / пазл). «Чему научитесь» на компьютере —
  всегда 6 карточек, вариант задаёт телефонную версию.
- **Режим «Для себя / Для организации».** Если у курса есть `org.modes` (сейчас — «Первая
  помощь детям»), на первом экране переключатель `parts/ModeSwitch.astro`; блоки рисуют
  обе версии с `data-mode`, видна одна. `?for=org` открывает режим организаций сразу;
  режим уходит в заявку полем `audience`.

### Ролики на коде

`components/film/` — «видео» без видеофайлов: сцены-анимации в SVG и CSS сменяют
друг друга, как сторис, с полосками прогресса и подписью к шагу. Весят как картинка.
- `Scene.astro` — 14 сцен (`FilmKind`): безопасность, оклик, проверка дыхания, звонок 103,
  компрессии (настоящий темп 110 в минуту), вдохи, дефибриллятор, давление на рану,
  повязка, жгут, кашель, удары по спине, толчки в живот, итог курса. Анимации идут
  только в активной сцене и перезапускаются при показе.
- `Film.astro` — проигрыватель: играет, пока виден на экране; тап по краям листает,
  кнопка — пауза; при «уменьшении движения» сам не листается. Счётчики `[data-count]`
  в сценах идут от времени сцены и останавливаются вместе с паузой.
- Сценарии роликов — `course.film` в данных курса. Тексты шагов — по рекомендациям
  ERC 2025 (взрослые, дети, первая помощь); при правке сверять с ними.
- Ролик стоит отдельным блоком «Ролик-алгоритм» и как вариант первого экрана «Ролик».

### Прочие интерактивы

- **Мини-тест** (`blocks/Quiz.astro`, `course.quiz`): 3 вопроса, после ответа — объяснение,
  в конце счёт и кнопка записи.
- **Ближайшая группа** (`course.nextGroup`) на первом экране показывается, только если в
  строке нет пометки или пометки включены: выдуманная дата не попадает на боевой сайт.
- **Прогресс чтения** — красная полоска под шапкой.
- **День по часам** — вариант программы из `course.schedule`, время пока примерное.

### Сертификаты

`parts/CertificateReal.astro` показывает настоящие образцы ЦКМ: основа — картинка
в `src/assets/certificates`, поверх в SVG в тех же координатах рисуются имя, номер,
дата, город и QR-код. Имя — типичное для страны, не реального выпускника.

- В присланных образцах — имена, номера и QR-коды реальных выпускников. На сайте их
  нет: основа собирается из PDF так, что эти поля берутся из рендера PDF без текста
  (`gs -dFILTERTEXT`), поэтому узор под ними сохраняется; QR-код закрашивается фоном.
  Новый образец готовится так же, координаты полей подгоняются по исходному рендеру.
- `bls-uz` — сертификат CCM Global (Ташкент), проверка на verify.medicaltraining.center.
  `bls-kg` — бланк самого ERC из презентации (Бишкек), проверка на cosy.erc.edu.
  `first-aid`, `first-aid-kids` — оформление по образцам ACLS и PALS CCM Global с
  названием курса для макета: реальных образцов первой помощи пока нет.
- QR-код на образце ведёт на сайт проверки без номера: чужие записи не показываем.

### Пометки «уточнить у ЦКМ»

В текстах `[[текст|вопрос]]` — правдоподобный пример на месте факта, которого мы
не знаем. `lib/rich.ts` в режиме разработки или при `PUBLIC_SHOW_MARKS=1`
подсвечивает его и показывает вопрос; в сборке без пометок оставляет текст и
перечисляет каждую оставшуюся пометку в логе сборки (`[уточнить у ЦКМ]`) — перед
боевым запуском этот список должен быть пустым.

- Цены: `price.amount` по странам и `price.confirmed`; пока `false`, цена выводится
  с пометкой (`lib/price.ts`). Отдельного блока стоимости по умолчанию нет — цена
  в секции заявки, в шторке и в вопросах.
- Отзывы-примеры (`REVIEWS_ARE_SAMPLES` в `data/about.ts`) в сборке без пометок
  не выводятся совсем: публикуются только реальные отзывы с согласием авторов.
- Клиенты: в Бишкеке — реальные названия из презентации ЦКМ (с пометкой о разрешении
  на показ), в Ташкенте пока отрасли: выдуманное название может совпасть с реальной компанией.

### Заявки и атрибуция

`lib/attribution.ts` при первом заходе ставит cookie `ccm_vid`, сохраняет UTM,
`fbclid` (из него — cookie `_fbc`) как первое и последнее касание. `LeadForm`
отправляет всё это на `PUBLIC_LEADS_ENDPOINT` вместе с `event_id`; тот же `event_id`
уходит в пиксель Meta, чтобы бэкенд отправил `Lead` в Conversions API без двойного
счёта. Без `PUBLIC_LEADS_ENDPOINT` форма работает в режиме макета.

## Правила

- **Сначала телефон.** Каждый блок проверяется на ширине 375 px.
- Стиль: белый фон, воздух, красный `--brand` как акцент, жёлтый `--sun` точечно.
  Без цветных полос по краю карточек.
- Сертификат — главный блок: по брифу информация должна быть больше о сертификате,
  чем о курсе.
- Логотип ERC — только в составе настоящего образца сертификата; отдельно на странице не используем, пока нет разрешения.
- Фото медицинской эвакуации (салон вертолёта с пациентами на носилках) не используем:
  оно связано с неприятным эпизодом в истории ЦКМ.
- Фото — файлы в `src/assets` через `<Picture>` / `<Image>` из `astro:assets` (Astro режет
  их на размеры и форматы avif/webp): флаги ЦКМ, сертификаты, инструкторы Бишкека.
  Остальные берутся с CDN Tilda (`data/images.ts`) и до боевого запуска переезжают в `src/assets`.
- Без горизонтальных лент, которые надо листать пальцем: на телефоне плитки 2 в ряд или список.
  Исключение — «Чему научитесь»: блок закрепляется, и обычная прокрутка вниз листает карточки вбок.
- Без эффекта «слайдов» (блоки, наезжающие друг на друга, доводчик прокрутки): пробовали, смотрится плохо.

## Запуск и публикация

```bash
cd landing && npm install && npm run dev
```

GitHub Pages: `.github/workflows/pages.yml` собирает `landing/` при каждом пуше
в `main` с `BASE_PATH=/CCM_landings` и `PUBLIC_SHOW_MARKS=1` и публикует на
https://mikhailvoskoboinikov.github.io/CCM_landings/. В настройках репозитория
источник Pages — «GitHub Actions». Все внутренние ссылки строятся через
`lib/url.ts`, иначе они не учтут подпапку.
